## 根本原因TOP5（パレート分析）

全fixの約80%がこの5つに集中。

### 1. UI/CSSを一発で完成させない（29件 = fix全体の36%）

- モーダル、レイアウト、スタイルで繰り返し修正
- 広告枠: 1 feat → 5 fix。ユーザー編集: 8連続fix
- **原因**: 実装前のデザイン検討不足、ブラウザテスト不足

### 2. DBスキーマ/フィールド名の不一致（19件 = 24%）

- `category` vs `inspection_type`、存在しないDB列の参照
- FAILURE_PATTERNS #2に記録済みなのに再発
- **原因**: 型チェックなし、スキーマとコードの同期メカニズムなし

### 3. import/export・モジュール依存の漏れ（12件 = 15%）

- `deleteProperty`未import、`showToast`未公開、`updateStats`未定義
- **原因**: ES modules + windowグローバルの混在アーキテクチャ

### 4. 防御的コーディング不足（12件 = 15%）

- null参照、try-catch不足、parseInt NaN
- 一括fixが何度も発生（同じ種類の修正を複数回に分散）
- **原因**: 初期実装時にエラーハンドリングを考慮しない習慣

### 5. テストせずに完了報告（横断的問題）

- 15テストでは主要CRUD・承認フローをカバーできていない
- Playwrightテスト実行の形跡がほぼない
- **原因**: テスト実行が習慣化されていない

## テストカバレッジの問題

テストは2ファイル15件のみ:
- `e2e-user-flows.spec.js`: ログイン・一件入力・一括入力（10テスト）
- `e2e-admin-flows.spec.js`: 管理者ログイン・タブ表示（5テスト）

**カバーされていない領域**:
- マスターデータCRUD操作（物件・保守会社・点検種別の追加/編集/削除）

- CSV/Excelエクスポート

## 改善策（優先順位順）

### 即効性: 今すぐ実行

#### 1. CLAUDE.mdを実行可能な最小限に削減

現在のCLAUDE.mdは参照ドキュメントへの誘導が多すぎて結局何も読まれない。
**本当に守るべきルール3つだけ**をCLAUDE.mdに直接書き、それ以外は削除:

```
ルール1: feat実装後、同じ機能のPlaywrightテストを追加・実行してPASSするまでコミットしない
ルール2: DB操作のコードを書く前に supabase/schema.sql でカラム名を確認する
ルール3: 新しいimport/exportを追加したら、関連する全ファイルのimport文を確認する
```

#### 2. pre-commitフックでPlaywrightテストを強制

ドキュメントで「テストしろ」と書いても実行されない以上、技術的に強制する:

```bash
# .husky/pre-push
npx playwright test --reporter=list
```

#### 3. ファイルの巨大さを解消

- `admin.html` (2,130行)、`admin.js` (2,462行) は見通しが悪く変更が壊れやすい
- 機能単位でファイル分割（マスター管理、承認管理、ユーザー管理等）

### 中期: 1ヶ月以内

#### 4. テストカバレッジを主要CRUDまで拡大

以下を追加:
- マスターデータの追加/編集/削除
- 承認・却下フロー
- フィールド名の正確性テスト（DBスキーマとの一致を自動検証）

#### 5. supabase-client.jsに型定義コメントを追加

TypeScript導入は大きすぎるので、まずはJSDocで各関数の引数・戻り値を明記:

```javascript
/**
 * @param {Object} data
 * @param {string} data.name - 物件名
 * @param {string} data.inspection_type - 点検種別（※categoryではない）
 */
```

#### 6. 改善ドキュメントを1ファイル50行以内に圧縮

- FAILURE_PATTERNS.md (414行) → 症状と対策だけのクイックリファレンス (50行)
- quality-first SKILL.md (388行) → 上記3ルールに統合して削除
- METRICS.md → 直近3セッションのみ保持

### 長期: 3ヶ月

#### 7. ESモジュール構造の整理

`window.showToast` 等のグローバル経由の依存をやめ、明示的なimport/exportに統一。
import漏れバグが構造的に解消される。

#### 8. CI品質ゲートの追加

- Playwright全テストPASS必須
- ESLintによるimport漏れ検出
- 未使用変数・関数の検出

## 核心メッセージ

**「ドキュメントを書くこと」と「ドキュメントに従うこと」は別の作業であり、後者が完全に欠落している。**

1,253行の改善ドキュメントを作る労力の10%でも実際のテスト実行に回していれば、fix率は大幅に下がっていたはず。

**最も効果的な改善策は「ドキュメントを減らし、技術的強制（pre-commitフック、CI）を増やすこと」。**
人間やAIの意志に頼るのではなく、仕組みで品質を担保するアプローチに転換すべき。
